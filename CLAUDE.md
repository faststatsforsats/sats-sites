# Working rules for this repository

This repository builds three sites for Jim Shaver: Fast Stats for Sats (faststatsforsats.com, the value of sats and bitcoin, charts first), Fast Facts for Sats (fastfactsforsats.com, how bitcoin works), and Fast Acts for Sats (fastactsforsats.com, how to buy, earn, store, secure, and use bitcoin). The full plan, style guide, backlog, and affiliate list live in the claude.ai Project "Alternate domains for experiements"; the short version you need is here.

## Build and check

- `python3 -m pip install -r requirements.txt` then `python3 build.py all --strict`. The build must exit 0 before a pull request is opened.
- Output goes to `sites/<site>/dist/`, which is ignored by git. Never commit it.
- `README.md` holds the Cloudflare Pages settings. If you change the build command or output folder, change the README in the same pull request.

## Where things go

- A page is a Markdown file under `content/<site>/<section>/<slug>.md`. Front matter fields are documented at the top of `lib/content.py`. Sections are declared in `sites/<site>/site.yml`; add a section there before adding a folder.
- Templates: `shared/templates/`. Styles: `shared/static/site.css`. Chart style: `lib/chartstyle.py`. Redirects: `go/redirects.csv`.
- Four pages are written once, in `content/shared/`, and built into all three sites at the same address: `/privacy/`, `/affiliate-disclosure/`, `/terms/`, `/contact/`. Each names itself in every footer with `footer_label`. They are written to cover the three sites together ("these sites"), so one text is true on each. When the text of one changes, change its `updated` date in the same edit: the privacy policy and the terms tell readers that the date at the top moves when they change.
- The privacy policy says what the sites do today, and it has to stay true. Before adding anything that changes the answer (a form that takes an email address, a script or font or image loaded from another company's servers, a cookie, anything kept in the browser, a new analytics tool), update `content/shared/privacy.md` in the same pull request. Step 25 of the Build Recipe adds the beehiiv subscribe form: that pull request adds the newsletter to the policy and takes "no sign-up forms" out of its first paragraph.
- The affiliate disclosure's list of active programs is `[[programs]]`, filled on every build from the rows of `go/redirects.csv` whose status is `approved`. It tells readers that a page with affiliate links always shows the disclosure line and that a page without the line has none, so the build fails on a `/go/` link in a page body whose template does not print the line (`DISCLOSING_TEMPLATES` in `lib/site.py`).
- `/go/<slug>` redirects only for an `approved` or `closed` program. For any other status the build writes a page at `/go/<slug>/` that says the link is not live (`shared/templates/go_pending.html`); see `go/README.md`.
- Embeds: `sites/stats/static/embed.js` is the sats badge other sites load from https://faststatsforsats.com/embed.js. It is a public address: keep `a.sats-badge`, `data-amount`, `data-currency`, and `data-label` working, keep it free of cookies, browser storage, and any request beyond the price, and put every figure and label into the badge as text, never as markup. The code a site pastes is defined once, in `shared/templates/_embed.html`, for the chart pages and for `/tools/embed/`, which shows the badge and one chart the way another site would (`[[embed:badge]]` and `[[embed:chart:<slug>]]` in its Markdown). Those embeds use the public addresses on purpose, so on a pages.dev preview they show only once faststatsforsats.com serves the site. The alt text in a chart's embed code is the page's title, which stays true on someone else's page; the dated finding would not.
- Data and charts are written only by the Daily Build (`scripts/daily_build.py`, 09:00 UTC). Do not edit `data/` or `charts/` by hand. A change to the words or layout of a chart reaches the site when the Daily Build next runs (Actions, Daily Build, Run workflow); do not upload redrawn charts. An `--offline` redraw is for looking only: a `data/network.json` saved before the Daily Build kept nine significant figures (October 2026) holds the hash rate in whole terahashes, so early 2011 draws flat from it until a real run has saved the series again.
- The Stats site reads `data/` and `charts/` at build time through `lib/stats_data.py` (the `stats` object in templates) and generates `/sats/<amount>-<currency>/` and `/items/<slug>/` pages from them in `lib/site.py`. Everyday items are defined once, in `ITEMS` in `lib/stats_data.py`: the BLS series id, BLS's item name, and the names the pages use; `scripts/sources/bls.py` builds its request from the same table. Check a new item's id against BLS's item list (https://download.bls.gov/pub/time.series/ap/ap.item) before adding it; never type one from memory. An item's name states the unit BLS prices it in (a pound of white bread, not a loaf). The generated pages take their meta description from `description` in `amount_pages()` and `item_pages()` (the two index pages get theirs in `lib/site.py`), handed to `base.html` as `page_description`; word it so it stays true when the price moves, and say only what that page shows (the January table is on the US dollar amount pages only, and an item's table starts where its series does). A top-level page joins the header nav with `nav: true` and a short `nav_label`.
- A page can show today's figure with a token in its Markdown: `[[live:sats-per-dollar]]`, `[[live:price]]`, `[[live:sats-for:100:usd]]`, `[[live:money-for:100000]]`, `[[live:fee:fast]]`, `[[live:height]]`, `[[live:to-halving]]`, `[[live:supply]]`, `[[live:when]]` (or `[[live:when:fees]]`), `[[live:cpi]]`, `[[live:gold]]`. The build bakes the number from `data/latest.json` and `shared/static/live.js` refreshes it from the Worker; the full list is `expand_live` in `lib/site.py`. Four more are baked and never refreshed: `[[live:items]]` (how many everyday items the basket holds) and `[[live:sp500]]`, `[[live:sp500-usd]]`, `[[live:sp500-sats]]` (the S&P 500 row the comparisons page quotes in its text).
- In a template, a figure follows the live price when its element carries `data-live` (the keys are listed at the top of `live.js`). Every figure that sits in the same sentence or table as a live one must be live too, or the page disagrees with itself once the feed answers: the amount pages' bitcoin figure (`btc-for`) and nearby amounts, and every figure on the Money in sats list. A time stamp (`class="live-when"`) keeps the capital letter the page wrote: "As of" where it opens a line, "as of" inside a sentence. The fee note on the network page starts from the fee data's own time (`stats.fees_updated_text`), then takes the feed's.
- Placement boxes (`placements:` in front matter) may name a program before it is approved; the box and the disclosure line appear only once `go/redirects.csv` says `approved`. A `/go/` link written in the body must already be approved or the strict build fails. A campaign gets its own rows in the CSV (`kraken-first100k`, campaign `oct26`) so clicks can be told apart.
- A campaign page is `template: campaign` with `eyebrow` and `hook_chart` in its front matter (see the top of `lib/content.py`); the build copies the hook chart's PNGs from `charts/` into that site's dist. The Sats Stacker's Starter Checklist PDF in `sites/acts/static/` is drawn by `scripts/checklist_pdf.py` from the words in `scripts/checklist.yml`; its twelve acts mirror `content/acts/first-100k-sats.md` in shorter form, so change both together and run the script. On a campaign page the download line is the button in `shared/templates/_newsletter.html`, which sits at the end of the body, above the product boxes.
- Chart pages under `content/stats/charts/` are shared with the Daily Build: it owns the `chart` and `updated` front matter and the text between `<!-- auto:start -->` and `<!-- auto:end -->`. Write the explainer below the end marker and it is kept. The words inside the auto block come from the chart's entry in `scripts/chartbook.py`: `detail` (the sentence after the finding), `lead` (when the paragraph should not open with the title sentence), `column` (the small table's third heading), and `credit`. A chart page's title and search description are in two places, `heading` and `description` in that entry and `title` and `description` in the Markdown file; change both together. The small table's first row is labeled "latest", never "now": the figures are historical observations, not live quotes.
- Source credits: a page lists the sources whose data it shows in `attribution:` (the codes are the keys of `ATTRIBUTION_LINES` in `lib/site.py`) and the footer prints one line for each, with only the provider's name linked. Credit a source only on pages that show its data. The CoinGecko, FRED, and BLS wording is fixed by those providers' terms. alternative.me's terms want its credit right next to the reading, so the home page's box and the Fear and Greed page carry "Source: alternative.me" beside the figure as well as in the footer. Generated pages get their credits in `lib/site.py` (`credit_lines`).
- Words that belong to a whole site live in `sites/<site>/site.yml`: the tagline, the default search description, `section_descriptions` (the search description of each list page), `not_found_description` (the search description of the page for an address that does not exist; that page's heading and sentence are Jim's and are the same on all three sites, in `shared/templates/404.html`), and `sharing_card_line` (the line on `og.png`; after changing it run `python3 scripts/sharing_card.py <site>`, which redraws the card from the coin and wordmark files).

## Brand

- Jim's logos are the three coin renders (B plus a bar chart, a document, a lightning bolt) and the wordmarks "Fast Stats for Sats", "Fast Facts for Sats", "Fast Acts for Sats" with the middle word in orange. The header shows the coin and the wordmark image; never retype the site name as text in the header.
- Colors (tokens in `shared/static/site.css`): navy `#071829` for the header and footer band (the logo background), wordmark orange `#f97e1b` as the accent, `#b85300` when orange must read as small text on white, link blue `#0b63b5`; dark mode uses navy `#0b1a2b` pages with `#ffa14a` and `#5cc3ff`. Charts use the same palette (`lib/chartstyle.py`): orange first, blue second, and the Stats coin in the footer corner. The chart look (highlighted figure in the title, glow line and wash, latest-value pill, marked highs and lows, halving lines) lives in `lib/chartstyle.py` and `scripts/chartbook.py`; redraw from saved data with `python3 scripts/daily_build.py --offline`. Every word drawn on a chart must sit inside the image and clear of the line: `render_chart` makes a layout pass that moves the plot's left edge when the scale's labels are wide, `latest_pill` keeps the pill inside the right edge, and `mark_point` scores each tag's own box against the line, the other tags, and the plot's edges. After changing a chart, look at both PNGs.
- Assets: `shared/static/brand/<site>-coin.png` (112 px, transparent, used by every site for the family links), `sites/<site>/static/brand/` (wordmark.png, og.png 1200 by 630, coin-512.png for profiles), and the favicons in `sites/<site>/static/`. The source renders live with Jim; ask before redrawing anything.

## Writing rules (from the style guide)

- Write like a person talking to a smart friend. Short sentences, paragraphs of three sentences or fewer, American spelling, digits with units (4,100 sats, $79, 12%).
- Never use an em dash. The build fails on one. Use a comma, colon, semicolon, or period.
- Never use: streamline, seamless, delve, leverage, unlock, game-changer, revolutionary, empower, robust, cutting-edge, journey, ecosystem (as filler), unleash.
- The answer comes first: the first two sentences of a guide answer the question in its title.
- Bitcoin the network is capitalized; bitcoin the asset is lowercase; sats is lowercase. Explain "sats" the first time it appears on a page.
- No price predictions, no targets, no "will." No advice on how much anyone should buy, hold, or allocate.
- Every figure comes from `data/` or a named source with a URL and a retrieval time. We estimate nothing ourselves; where the source's own figure is an estimate (hash rate, fees), the page says so.
- Every Acts guide has `understand_first` in its front matter, linking the Facts explainer behind it.
- All three sites carry Jim's own text: he edits a Word copy and the edits go in word for word (Facts and Acts in step 19, Stats on October 2, 2026, including the titles, search descriptions, table labels, generated-page sentences, and the words drawn on the charts). Do not reword any of it; propose changes to him instead. New pages follow the same voice.
- The step 20 pages (the four in `content/shared/`, `/tools/embed/`, the "not live" page, the footer's four link names, "Copy the code" and "Copied", and the words in the badge) were drafted for Jim and went to him as a Word review copy on October 2, 2026. Once his edits are in, they are his text like the rest.
- A page says only what is true on the day it is read. The legal pages are written so they hold with no approved program and with twenty: "where a page carries an affiliate link", not "some links are affiliate links".
- When a link names a page, it uses that page's title (the home page's link list; "see Gold, homes, and the S&P 500 in bitcoin terms"); the short names are for the menu only. Links Jim wrote on a descriptive phrase ("sats converter", "sats per dollar chart") stay as he wrote them. Say "retrieved", not "pulled", for when data was fetched, and "estimate" for hash rate and fees.
- Figures that change at someone else's discretion (product prices, reward rates, most fees) are not quoted on Acts pages; the page says what to check and the Sources list links the provider's own page. Quote a third-party figure only when the page needs it to make sense, and name who lists it ("Unchained lists $250 per IRA per year").
- In a step-by-step guide a step heading is written `## <span class="step">Step 1</span> Choose a service`, so "Step 1" sits as a small label above the heading.
- Affiliate links are written only as `/go/{slug}` and only for programs with status `approved` in `go/redirects.csv`. Never a raw affiliate URL. Placement boxes go in the `placements:` front matter list, not in the body.
- Tax and IRA pages describe general rules and say a tax professional should be consulted for the reader's situation.

## Pull requests

- One topic per pull request, a title that says what changed, and a description Jim can read in a minute: what the change is, which pages it touches, and anything he should check in the preview.
- Never merge. Jim merges after reading the preview.
- Never commit a secret. Keys live in GitHub's secrets store (`COINGECKO_KEY`, `BLS_KEY`, `FRED_KEY`, `NOSTR_NSEC`) and in Cloudflare's Worker secrets.
